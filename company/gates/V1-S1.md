# Gate V1-S1 — Internal Provider Contract

## Gate question

> Stock CCR가 credential 사용 권한이 있는 사내 Windows host에서 사용 가능한 내부 모델 한 개를 upstream Provider로 사용해 basic completion, streaming, tool round-trip과 주요 오류 분류를 source 수정 없이 수행할 수 있는가?

현재 first available model은 Gemma다.
GLM은 serving rollout 완료 후 별도 onboarding을 수행한다.

## Role and host precondition

사내 검증자는 `INTERNAL_VALIDATOR`이며 pull-only다.
GitHub Task/STATUS/Gate 반영은 sanitized evidence를 받은 `CHATGPT_ORCHESTRATOR`가 수행한다.

Provider/gateway contract evidence에는 다음 두 조건이 필요하다.

```text
WINDOWS_RUNTIME_ALLOWED = YES
LLM_CREDENTIAL_AUTHORIZED_FOR_HOST = YES
```

Claude Code E2E에는 추가로:

```text
CLAUDE_CODE_EXECUTION_ALLOWED = YES
```

현재 세 capability는 모두 `YES`로 확인됐다.

## Current protocol decision

현재 Gemma V1 공식 upstream protocol:

```text
openai_chat_completions
```

Observed capability:

| Protocol | Result | Gate meaning |
|---|---|---|
| OpenAI Chat Completions | `PASS` | V1 supported path |
| OpenAI Responses | `FAIL`, HTTP `500` | `UNSUPPORTED_OR_INCOMPATIBLE`, non-blocking, deferred |

Responses 실패는 Provider 전체 실패로 계산하지 않는다.
현재 Gate는 검증된 Chat Completions 경로로 계속 진행한다.
Responses가 실제 요구사항이 되거나 사내 공식 지원이 확인되면 별도 compatibility Task를 만든다.

## Required evidence

- Gemma Provider 저장·영속화와 한 모델의 Chat Completions connection check
- CCR local gateway를 통한 Gemma basic client completion
- streaming 정상 종료
- tool call 생성과 tool result continuation
- 최소 오류 분류: credential host scope, auth/permission, rate limit, upstream 5xx, timeout 또는 network
- Request logs/body capture 안전 설정
- product source/lockfile 무변경
- secret, actual host/IP, raw internal evidence 비노출
- Gemma 권장 workload 범위 또는 제외 근거

GLM과 OpenAI Responses는 현재 Gate를 막지 않는다.
다만 GLM-specific V1-S2 coding loop 전에 GLM Provider와 gateway basic completion을 별도로 통과해야 한다.

## Scope control

- 한 번에 검증 질문 하나만 수행한다.
- Provider-level check와 client gateway request를 서로 다른 Task evidence로 취급한다.
- Host-scope blocker, availability 오류, protocol 오류, model quality 실패를 혼합하지 않는다.
- 실제 endpoint, key, model ID, host/IP, raw prompt/response, internal hostname은 외부 Evidence에 기록하지 않는다.
- 실패를 우회하기 위한 CCR source/dependency patch를 먼저 하지 않는다.
- Credential 공유, proxy/tunnel, allowlist 우회를 사용하지 않는다.
- Internal Validator에게 GitHub write를 요구하지 않는다.

## Remaining risks

- V1-S1-T01 Provider 저장·영속화, logging safety, stop, clean-tree evidence가 아직 필요하다.
- Provider `Check Connection` PASS만으로 local gateway, streaming, tools, Claude Code compatibility를 증명할 수 없다.
- `/v1/responses` 공식 사내 지원 여부와 CCR compatibility는 미확정이다.
- GLM serving rollout과 GLM-specific onboarding은 완료되지 않았다.
