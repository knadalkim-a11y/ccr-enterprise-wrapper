# Gate V1-S1 — Internal Provider and Gateway Contract

## Gate question

> Stock CCR가 credential 사용 권한이 있는 사내 Windows host에서 Enterprise Claude 환경을 변경하지 않고, 사용 가능한 내부 모델 한 개로 Provider persistence, basic completion, Streaming, Tool round-trip과 주요 오류 분류를 source 수정 없이 수행할 수 있는가?

현재 first available model은 Gemma다.
GLM은 serving rollout 완료 후 별도 onboarding을 수행한다.

`V1-S1-T00`이 FAIL이면 Provider protocol evidence는 보존하되 Gate 진행을 중단하고 isolation repair를 재평가한다.
Attempt 1은 Enterprise breach가 아니라 금지된 `Connect agent` 없이 cleanup/save 경로에 도달할 수 없었던 `BLOCKED_POLICY — CONFIG_SAVE_PATH_UNAVAILABLE`였다. T02는 wrapper-only 범위에서 syntax PASS, 159/159 synthetic/mock tests와 tested product 대비 protected CCR source/build/package path equivalence를 통과해 `EXTERNAL_PASS`다. Candidate/full-head build equivalence는 테스트하거나 주장하지 않는다. T00 Attempt 2는 `c2459b90182041afdb7b9c0cf44149494b30f910`의 A0에서 `BLOCKED_TOOLCHAIN_IDENTITY`로 중단됐지만 기존 capsule은 exact checkpoint를 보존하지 못했고 post-block diagnostic은 실행되지 않았으며 console은 닫혔다. 그 뒤 Internal Sonnet이 repository authority 불일치를 지적하고 아무 명령도 실행하지 않은 건은 Attempt가 아니다. ## Remaining risks

- process-local LOCALAPPDATA의 management start isolation은 한 번 통과했지만 wrapper-assisted config-save isolation은 내부 미검증이다.
- Attempt 2 A0의 toolchain identity failure는 exact checkpoint가 capture되지 않아 원인 미확정이다. Post-block diagnostic은 `NOT_RUN`, console은 `CLOSED`다. `npm.ps1` precedence는 유력 후보였을 뿐 확정 원인이 아니다.
- Exact `e16...` A0의 Windows PowerShell 5.1, source/product identity, Node/npm binding, install/typecheck/build는 Human-transcribed sanitized Evidence상 PASS다. Orchestrator가 내부를 독립 재실행한 사실이나 successor-head PASS로 확대하지 않는다.
- A0 build plane은 full validated product `97b73a9...`이고 candidate Task/script/T02 artifact는 별도 exact overlay plane이다. Tailwind의 repository-wide source scan 때문에 current main/PR full-head build equivalence와 merge safety는 `NOT_TESTED / NOT_CLAIMED`이며 eventual merge/release 전에 별도 결정이 필요하다.
- A0 PASS는 T00 PASS, T02 internal PASS, repair merge 승인 또는 H0 승인이 아니다.
- unfinished onboarding에서 required cleanup으로 들어갈 supported stock UI 경로가 없다.
- CCR `packages/**` patch는 Human Gate가 거부됐고 Company-only helper만 external PASS했다.
- Helper 단독으로 daemon `LOCALAPPDATA` 또는 atomic CAS를 증명할 수 없으므로 future runtime은 fresh service ownership, relevant current-user writer quiescence와 unconditional cleanup/invariance를 별도로 증명해야 한다.
- canonical config store metadata는 DB row/schema fixed point나 write-free first open을 증명하지 않으므로 legacy migration source absence가 필수다.
- 공유 PC에서 state check와 stock stop 사이의 micro-race가 남아 있다. 다른 Windows 사용자 세션 전체 종료는 필요 없지만, 같은 account 동시 사용 또는 relevant process/port owner 불명은 runtime blocker다.
- H0 minimal design은 승인됐지만 active Sonnet도 current-user Claude writer이므로 source verification/materialization 뒤 종료해야 한다. Runtime은 아직 구현되지 않은 reviewed one-shot plain-PowerShell controller와 새 exact head/Attempt 4가 필요하다.
- Attempt 3 A0 workspace `4b5fc...`에는 post-A0 dependency/build seal이 없다. Evidence용으로 보존하며 new ref/runtime root로 자동 재사용하지 않는다.
- Stock default `requestLogBodyCapture="all"`과 helper required fixed point `"none"`의 실제 config 충돌 가능성은 future no-save preflight에서만 판단한다. 추정으로 config를 고치지 않는다.
- single local nonce validation workspace는 sanitized 32-hex ID를 Evidence에 남기고 Gate review 뒤 Human exact-nonce cleanup이 필요하다.
- 기존 CCR runtime config에 stale global profile marker가 있을 수 있으며 saved global count는 미검증이다.
- `start --no-gateway`가 기존 service를 재사용할 수 있으므로 service identity와 pre-save Gateway stopped 상태를 별도로 증명해야 한다.
- wrapper RPC save 전에 enabled Provider `autoFetchModels = OFF`를 확인하지 않으면 즉시 model refresh가 예약될 수 있다.
- Stock Management RPC는 pinned-version source contract이며 upstream update 때 재검증해야 한다.
- sandbox 환경이 app discovery나 child inheritance에 영향을 줄 수 있다.
- Provider persistence, local gateway, Streaming, Tool, error matrix는 미검증이다.
- `/v1/responses` 공식 지원 여부는 미확정이다.
- GLM serving rollout이 완료되지 않았다.

## Recommendation

`RECORD ATTEMPT 3 A0 + H0 DESIGN; IMPLEMENT AND REVIEW THE MINIMAL COMPANY CONTROLLER WITH ITS SAME-HEAD CANONICAL READY_INTERNAL TRANSITION; THEN FREEZE AND HUMAN-APPROVE THE EXACT ATTEMPT 4 RUNTIME HEAD`.

T02는 `EXTERNAL_PASS`지만 internal runtime validation은 `NOT_STARTED`다. CCR `packages/**`는 수정하지 않는다.
이번 design head의 authorized phase는 `NONE`이다. Future implementation lane은 controller/test와 T00/T02/project-state/STATUS/Gate만 쓰고, 같은 final runtime head에 controller `IMPLEMENTED / EXTERNAL_REVIEW_PASS`, `ready_internal`과 `ATTEMPT_4_PREPARE_AND_H0_RUNTIME_AFTER_EXACT_HEAD_HUMAN_APPROVAL`을 동기화해야 한다. Freeze 뒤 승인용 docs commit을 추가하지 않는다. Human이 그 exact head를 승인해야만 conditional phase가 실행 가능하다. Future runtime head는 `human_assisted`, `WINDOWS_RUNTIME_ALLOWED=YES`, `CLAUDE_CODE_EXECUTION_ALLOWED=YES`가 필요하고 CCR/internal-model credential capability는 H0/T00에 필요하지 않다. Ref/SHA/Task/controller bootstrap mismatch면 `PRE_EXECUTION_HANDOFF_BLOCKED`로 Attempt 4를 소비하지 않는다. Exact reviewed controller `-Prepare` process가 성공적으로 시작되면 Attempt 4가 시작되고, 그 뒤 preparation failure도 formal Attempt result다. Runtime은 actual Enterprise targeted invariant를 service 실행 중 `DURING=SAME`, cleanup 뒤 `AFTER=SAME`으로 각각 증명해야 한다.
