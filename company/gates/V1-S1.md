# Gate V1-S1 — Internal Provider and Gateway Contract

## Gate question

> Stock CCR가 credential 사용 권한이 있는 사내 Windows host에서 Enterprise Claude 환경을 변경하지 않고, 사용 가능한 내부 모델 한 개로 Provider persistence, basic completion, Streaming, Tool round-trip과 주요 오류 분류를 source 수정 없이 수행할 수 있는가?

현재 first available model은 Gemma다.
GLM은 serving rollout 완료 후 별도 onboarding을 수행한다.

## Role and host precondition

사내 검증자는 `INTERNAL_VALIDATOR`이며 pull-only다.
GitHub 반영은 sanitized evidence를 받은 `CHATGPT_ORCHESTRATOR`가 수행한다.

## Isolation precondition

V1-S1의 real Provider save와 gateway request 전에 `V1-S1-T00`을 통과해야 한다.

Required invariant:

```text
CCR service process
→ sandbox LOCALAPPDATA

Enabled global/System-default Claude Code profile
→ 0

Enterprise %USERPROFILE%\.claude\settings.json
→ unchanged

Actual %LOCALAPPDATA%\Claude-3p
→ unchanged

User/Machine CCR env
→ unchanged

Normal claude Enterprise smoke
→ before/during/after PASS

Manual rollback
→ NOT_REQUIRED
```

`Only opened from CCR`는 Claude Code profile settings를 격리하지만, management start/config save의 Claude App sync까지 차단하지 않으므로 runtime sandbox evidence가 별도로 필요하다.

`V1-S1-T00`이 FAIL이면 Provider protocol evidence는 보존하되 Gate 진행을 중단하고 isolation repair를 재평가한다.
Attempt 1은 Enterprise breach가 아닌 onboarding policy precondition 부재로 `BLOCKED`됐다. Human Gate는 CCR source patch를 거부하고 `2026-09-01`에 Stock authenticated Management RPC를 사용하는 Company-only `V1-S1-T02` 구현을 승인했다. T02는 wrapper-only 범위에서 syntax PASS, 159/159 synthetic/mock tests와 product tree equivalence를 통과해 `EXTERNAL_PASS`다. 내부 runtime 검증은 `NOT_STARTED`이며 T00 Attempt 2는 exact frozen head의 A0만 승인된 `READY_FOR_INTERNAL_VALIDATION` 상태다.


## Scope control

- 한 번에 검증 질문 하나만 수행한다.
- T00 runtime isolation, T01 Provider persistence, completion, Streaming, Tool을 분리한다.
- Host-scope, isolation, protocol, availability, quality failure를 혼합하지 않는다.
- 실제 endpoint/key/model ID/host/IP/raw prompt/response는 외부 Evidence에 기록하지 않는다.
- 실패를 우회하기 위한 source/dependency patch를 먼저 하지 않는다.
- `System default` Claude Code profile을 사용하지 않는다.
- actual LOCALAPPDATA에서 Stock CCR start/save를 수행하지 않는다.
- Internal Validator에게 GitHub write를 요구하지 않는다.

## Remaining risks

- process-local LOCALAPPDATA의 management start isolation은 한 번 통과했지만 wrapper-assisted config-save isolation은 내부 미검증이다.
- unfinished onboarding에서 required cleanup으로 들어갈 supported stock UI 경로가 없다.
- CCR `packages/**` patch는 Human Gate가 거부됐고 Company-only helper만 external PASS했다.
- Helper 단독으로 daemon `LOCALAPPDATA` 또는 atomic CAS를 증명할 수 없으므로 fresh A2 ownership, H0 all-writer quiescence와 unconditional A3가 필요하다.
- canonical config store metadata는 DB row/schema fixed point나 write-free first open을 증명하지 않으므로 legacy migration source absence가 필수다.
- 공유 PC에서 state check와 stock stop 사이의 micro-race가 남아 있어 모든 CCR writer를 닫은 상태를 유지해야 한다.
- A0부터 A2–A3까지 동일한 전용 64-bit PowerShell process를 유지해야 한다.
- local nonce validation workspace는 Gate review 뒤 Human exact-nonce cleanup이 필요하다.
- 기존 CCR runtime config에 stale global profile marker가 있을 수 있으며 saved global count는 미검증이다.
- `start --no-gateway`가 기존 service를 재사용할 수 있으므로 service identity와 pre-save Gateway stopped 상태를 별도로 증명해야 한다.
- wrapper RPC save 전에 enabled Provider `autoFetchModels = OFF`를 확인하지 않으면 즉시 model refresh가 예약될 수 있다.
- Stock Management RPC는 pinned-version source contract이며 upstream update 때 재검증해야 한다.
- sandbox 환경이 app discovery나 child inheritance에 영향을 줄 수 있다.
- Provider persistence, local gateway, Streaming, Tool, error matrix는 미검증이다.
- `/v1/responses` 공식 지원 여부는 미확정이다.
- GLM serving rollout이 완료되지 않았다.
